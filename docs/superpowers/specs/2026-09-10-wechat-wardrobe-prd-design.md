# 电子衣橱微信小程序 PRD（设计规格）

- **文档日期**：2026-09-10
- **产品代号**：电子衣橱（暂定名，上线前可品牌化）
- **平台**：微信小程序
- **产品策略**：方案一 ——「今日穿搭操作系统」
- **文档状态**：待产品负责人审阅后进入实现计划

---

## 1. 背景与目标

### 1.1 问题

用户不是缺少衣服，而是每天早上缺少一个「今天穿什么、为什么这么穿」的快速决策。传统电子衣橱往往停在「拍照存档」，打开理由弱、录入成本高，导致留存差。

### 1.2 产品目标

做一款**通用向**的微信电子衣橱：以「今日穿搭」为每日主引擎，用天气与日程给出硬理由，用情绪主题与连续打卡提高粘性；同时用四个 Tab 覆盖盘点、护理、灵感，并把虚拟体验渐进沉淀为真实衣橱资产。

### 1.3 成功标准

| 层级 | 指标 | 说明 |
|------|------|------|
| 北极星 | 打开率 / 日活习惯 | 例如：注册用户「周打开 ≥ 3 天」占比；以实验最终定阈值 |
| 过程 | 穿搭采纳率 | 进入「今日」后点击「今天穿这套」的比例 |
| 过程 | 连续出门日 | streak ≥ 3 的用户占比；D1/D7 留存 |
| 资产 | 衣橱完整度 | 人均有效入库件数、识别确认率、推荐中真实单品占比 |
| 商业 | 会员转化 | 免费识别额度触顶率 → 会员转化；订阅消息点击回访率 |

## 2. 用户与定位

### 2.1 目标用户

**通用版**：不预设单一人群。通过轻量画像（城市、常去场景、风格标签）让用户自我定义，推荐与文案保持中性可配置，避免绑死「仅上班族」或「仅穿搭达人」。

### 2.2 一句话定位

每天根据天气与日程告诉你「今天穿什么」，并帮你把衣柜变成越用越准的个人穿搭系统。

### 2.3 产品原则

1. **打开即有用**：空衣橱也能完成一次「今日方案」体验。
2. **每套必有理由**：推荐必须带可读的「今日理由条」。
3. **真实化可见**：虚拟 → 真实的进度要对用户可见，形成补录动力。
4. **四个 Tab 完整但克制**：都有独立闭环，但都服务「今日」打开率。
5. **免费能养成习惯，会员买深度**：主路径不锁死；额度与高级能力进会员。

---

## 3. 产品形态与信息架构

### 3.1 底部四个 Tab

| Tab | 名称 | 职责 | 与打开率关系 |
|-----|------|------|--------------|
| 1（默认） | **今日** | 天气 + 日程 + 情绪主题 → 今日方案 → 采纳/微调 → 打卡 | 主引擎 |
| 2 | **衣橱** | 拍照入库、分类、穿着频率、闲置洞察 | 提升推荐质量 |
| 3 | **护理** | 洗涤/保养、换季收纳、断舍离候选 | 订阅消息回流 |
| 4 | **灵感** | 轻社交：打卡、收藏、周主题、复刻 | 分享与再打开 |

### 3.2 全局能力（非 Tab）

- 微信登录与用户资料
- 轻量画像：城市天气、常去场景、风格标签
- 会员权益与额度账户
- 订阅消息：出门前提醒、护理/换季提醒
- 分享：穿搭卡片分享至好友/朋友圈

### 3.3 创意差异点（必须写入体验）

1. **今日理由条**：例如「今早 12°C 有雨 + 下午客户会 → 防水外套 + 正式感内搭」。
2. **虚拟→真实渐进**：空柜用模板衣柜；每入库一件，推荐卡展示「真实单品 x/y」。
3. **连续出门日**：采纳即打卡；断签用「补穿回忆」软挽回，不做重度惩罚游戏。

---

## 4. 核心用户流程

### 4.1 首次进入（目标 60–90 秒）

1. 微信授权登录
2. 选择城市（天气）
3. 选择 2～3 个常去场景（通勤 / 约会 / 运动 / 居家等，可多选）
4. 可选风格标签（简约 / 休闲 / 正式 / 运动等）
5. **不强制传衣**，直接进入「今日」，使用虚拟单品模板生成第一套方案，并提示可稍后拍照入库

### 4.2 每日主路径（目标：打开后约 30 秒可决策出门）

1. 进入「今日」：天气摘要 + 今日日程入口（可空）+ 情绪/主题 chips（元气 / 低调 / 显瘦 / 省事等）
2. 系统输出 **1 套主推荐 + 2 套备选**，每套含「今日理由条」
3. 用户可：替换单品 / 换整套 / 切换主题后重推
4. 点击 **「今天穿这套」**：
   - 记录穿着（真实单品累加次数；虚拟单品不计入衣橱统计）
   - 计入连续出门日
   - 可生成打卡图（默认仅自己可见，可选择发到「灵感」或微信分享）
5. 引导开启订阅消息：「明天出门前提醒」（可跳过）

### 4.3 虚拟 → 真实渐进

- 推荐卡展示真实单品占比进度
- 缺真实件时 CTA：「拍照补这件，推荐会更准」→ 跳转衣橱入库 → 返回刷新方案
- 未形成有效衣橱前，护理/闲置能力以说明与引导为主，不阻断「今日」主路径

### 4.4 异常与兜底

| 情况 | 处理 |
|------|------|
| 天气接口失败 | 使用缓存/昨日或让用户选手动体感；理由条改为场景 + 主题 |
| 日程为空 | 仅天气 + 主题，不强迫填日历 |
| 推荐失败 | 回退「经典万能搭配」模板 + 引导补齐基础品类 |
| 识别失败 | 保留原图，引导手动选品类/颜色后入库 |
| 订阅消息未授权 | 功能降级为站内提醒入口，不反复强弹 |

## 5. 功能需求详述

### 5.1 Tab「今日」

**必做（MVP）**

- 天气展示（城市、温度、天气现象、穿衣相关提示）
- 日程：当日简易事件（标题 + 时段 + 正式度标签）；一期支持手动添加，不强制系统日历同步
- 情绪/主题选择与重推
- 推荐结果：主推荐 + 备选；单品级替换
- 今日理由条（规则/模板生成，可后续升级模型）
- 「今天穿这套」、连续出门日、打卡图生成
- 与衣橱真实单品/虚拟模板的混合搭配展示

**会员增强**

- 更高的换套/微调次数（或按日无限）
- 一日多场景方案（如通勤套 + 晚饭套）

### 5.2 Tab「衣橱」

**必做（MVP）**

- 拍照入库：上传/拍摄 → AI 抠图与分类建议（品类、颜色、季节）→ 用户确认/修改 → 保存
- 列表与筛选：品类 / 季节 / 颜色
- 单品详情：图片、标签、穿着次数、最近穿过日期
- 基础洞察：长时间未穿提醒（阈值可配置，默认 60 天）、同色同品类偏多提示
- 「加入今日搭配」回流

**会员增强**

- 更高拍照识别额度（免费额度建议默认每月 20–30 次，具体可配置）
- 批量导入（二期可加深；一期若做仅会员）

### 5.3 Tab「护理」

**必做（MVP）**

- 单品护理标签（面料、洗涤方式等，可入库时或事后补充）
- 洗涤/护理建议页
- 至少 1 类订阅提醒（如「该洗衣物」或「换季收纳」二选一作为默认主提醒）
- 轻量断舍离：基于穿着频率给出「可捐赠/可转卖」候选列表；用户确认后归档，不自动删除

**会员增强**

- 多类提醒 + 换季清单生成

### 5.4 Tab「灵感」

**必做（MVP）**

- 个人穿搭打卡流（默认私密）
- 收藏「我想穿」
- 官方周主题（运营可配置内容位）
- 分享卡片到微信
- 「用我的衣橱复刻」：能匹配则生成「今日」方案草案；不能则提示缺少的品类

**明确不做（一期）**

- 公开大广场、关注链、私信、直播
- 完整电商下单与支付购衣
- 多成员家庭共享衣橱

### 5.5 会员与商业

- 模式：基础免费 + 会员
- 免费必须保证：每日能看到带理由的主推荐并完成采纳打卡
- 会员售卖点：识别额度、高级推荐（多场景/更多微调）、护理提醒深度、去广告（若存在广告位）
- 价格与具体次数：PRD 锁定权益逻辑；数值上线前 A/B 或运营配置

## 6. 推荐与数据逻辑（产品层）

### 6.1 推荐输入

- 天气：温度、降水、风等
- 日程正式度（无则中性）
- 用户主题/情绪
- 可用单品池：真实衣橱 ∪ 虚拟模板（按画像场景过滤）
- 历史：近期穿过（降低重复）、闲置激活加权

### 6.2 推荐输出

- 结构化搭配（上装/下装/鞋/外套等槽位，按季节可见）
- 今日理由条文案
- 真实单品占比
- 可替换候选列表（同槽位）

### 6.3 一期实现策略

- 优先 **规则 + 模板槽位匹配**，保证可解释、可控、成本低
- AI 侧重 **入库识别与抠图**；生成式穿搭文案可模板化，后续再升级
- 不在一期承诺「完全个性化造型师」效果，而以「有理由、可微调、越用越像自己的柜子」为验收标准

---

## 7. 信息与权限（微信）

- 登录：微信授权
- 位置/城市：优先用户手选城市；若用定位需说明用途（天气）
- 相册/相机：仅用于入库与打卡
- 订阅消息：出门前提醒、护理/换季；遵循一次性授权与模板规范
- 内容安全：用户上传图与公开分享内容需过审/检测（按微信要求）

---

## 8. 非功能需求

- **性能**：今日首页关键数据首屏可感知时间目标 < 2s（常规网络）
- **可用性**：主路径（看推荐 → 采纳）不超过 3 次必要点击
- **可靠性**：天气/识别失败必须有降级，不可白屏
- **可运营**：周主题、虚拟模板包、会员额度、闲置天数等可后台配置
- **隐私**：打卡默认私密；分享为显式行为

---

## 9. 范围切割

### 9.1 一期 MVP（必须交付）

- 四 Tab 骨架与上述各 Tab「必做」能力
- 虚拟冷启动 + 拍照入库主路径
- 天气 + 手动日程 + 主题 + 理由条 + 采纳打卡 + streak
- 会员：识别额度 + 换套次数差异
- 订阅消息至少打通 1 条主提醒链路

### 9.2 二期及以后

- 系统日历同步、更细日程智能
- 公开社区与关注关系
- 愿望单 / 品牌导购 / 轻电商
- 家庭多成员衣橱
- 更强的生成式搭配与虚拟试衣
- 深度断舍离交易闭环

---

## 10. 验收要点（产品）

1. 新用户不上传衣服也能在首次会话内得到带理由的今日方案。
2. 有天气与场景时，理由条能读出「为什么是今天这套」。
3. 入库真实单品后，今日推荐中真实占比上升且可感知。
4. 「今天穿这套」后能看到连续出门日变化，并可生成打卡图。
5. 免费用户每日主路径可用；触顶识别/换套时出现清晰会员转化点且不阻断查看已有方案。
6. 四个 Tab 均可独立完成至少一次完整任务并回到「今日」。

## 11. 开放配置项（上线前标定）

- 免费月识别次数 N、每日免费换套次数
- 闲置未穿天数阈值
- 默认提醒类型与发送时间窗
- 虚拟模板包与周主题内容
- 北极星指标的具体数值目标

---

## 12. 设计结论

采用 **「今日穿搭操作系统」**：默认 Tab 为「今日」，以天气 + 日程为硬理由，情绪主题与连续打卡为粘性；衣橱、护理、灵感完整但克制，服务真实化与回流；商业上基础免费 + 会员加深识别与高级推荐。一期用规则化可解释推荐保证体验稳定，AI 优先用于入库识别，避免空心社区与重电商稀释主路径。
